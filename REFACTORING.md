## D. Data model

- [x] **D1. Restructure the `Element` god-struct (~45 fields).** Extracted `EntryListState` (listCollapsed, listScrollY, selectedEntryId, kindList, selectedKind, and the caching fields added in E4/E7) and `SphereState` (model, camera, renderTexture, rotation) as arena-allocated, pointer-referenced (`e->entryList`, `e->sphere`) structs instead of flat `Element` fields — allocated on demand in `make_entry_list`/`make_sphere`, NULL otherwise. Measured before/after: `sizeof(Element)` was 7280 bytes, ~93% of it (`kindList` + `cachedEntries`) unconditionally paid by all `MAX_ELEMENTS=10000` elements even though at most one is ever an entry list; `State` (which embeds `Element[MAX_ELEMENTS]`) was ~69.4MB. This is a real, measured fix, not just style. Did **not** do the full union-based split (TextEditorState as a third arm) originally proposed: `ELEM_ENTRY_LIST` isn't a mutually-exclusive alternative to `ELEM_TEXT_EDITOR`, it's a superset (`make_entry_list` calls `make_text_editor` and both kinds share the gap-buffer/selection/scroll/key-repeat fields identically via flat `Element` access throughout the codebase). Unioning those out would require adding an accessor layer to every shared code path for comparatively little memory benefit (at most 1-2 such elements ever exist), a much larger and riskier change than the entry-list/sphere extraction that fixes the actual measured bloat.
- [x] **D2. Extract a standalone `GapBuffer` struct.** `lcars_gap_buffer.h` functions now take `GapBuffer *`/`Selection *` instead of `Element *`, touching only `buffer/gapStart/gapEnd/capacity` and `start/length/end` respectively — no `Element` or raylib-type dependency in the module itself (`Element` still embeds `GapBuffer gap;`/`Selection selection;` by value, since both editor kinds share them identically). Moved `EndTextSelection`'s unconditional `snapToCursor = 2` side effect out to its 5 call sites, since `snapToCursor` is an `Element`-level view concern, not gap-buffer or selection state. Verified with a standalone test (arena + GapBuffer/Selection only, no Element) covering insert, buffer growth, backspace/delete, shift-selection, DeleteSelection, and FindWordBoundary — all 14 checks passed.
- [x] **D3. Replace `float *width, *height` with plain floats.** `Element.width`/`height` are now plain floats; removed the two arena_alloc'd single-float allocations per element in lcars_hypermedia.h that existed purely to support the pointer indirection. Added an explicit `bool autoSize` for `make_text`'s "size from text, not width/height" case (previously encoded as `width == NULL`), and simplified `GetElementBoundingBox`/`IsHoveringElement`'s now-impossible NULL checks away for the other kinds.
- [x] **D4. Add element `id`s to hypermedia and a `FindElementById()`, then remove positional hacks.** Added `String id` to `Element`, parsed from a new `id="..."` hypermedia attribute, plus `FindElementById()` (defined directly in liblcars.h alongside `updateNotification`, since it's needed by `make_sphere()` before `lcars_ui.h` is included — matches that function's existing "needed early" precedent). Replaced `s->elements[0]` (the "Hack: the first element doubles as the URL input" comment) with `FindElementById(s, "url_input")`, and the sphere status rectangle's position-(0,4) match with `FindElementById(s, "sphere_status")`; added the matching `id` attributes to main.html. Documented and kept the existing behavior for unquoted values (`attr=value` with no quotes): treated the same as "not found" — `dest` untouched, returns `false` — since nothing in this document format writes unquoted values. ## Suggested order

A (1-3 especially) → B1/B2 → C1-C7 → E1-E7 → D1-D4 → F, G, H, I in any order. A and B are prerequisites that make every later diff smaller; C and E remove the bulk of duplication; D is the deepest structural change and benefits from the code already being in small functions.
